# 召回评测标注

一个角色一个文件：`tests/eval/recall/<名字>.jsonl`，一行一条查询。`TEMPLATE.jsonl`
是格式示例（人物与句子都是假设的，不要直接跑）。

## 口径（Shiyu 2026-10-25 定）

> 他没参与就不应该知道；亲历、目击、被当面告知、自己偷听到、自己读到的 → 知道；
> 背着他发生、只被别人提到的 → 不知道。

## 每行的字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 文件内唯一，如 `q01` |
| `phase` | 是 | 聊天时选的阶段（决定检索上界 `window`） |
| `query` | 是 | 用户会问的那句话 |
| `should` | 是 | 该找回的原文片段，可多条，命中任一即算 |
| `should_not` | 否 | 他不该知道的原文片段，可为空数组 |
| `note` | 否 | 给自己看的备注 |

## 片段规则（脚本会在检索前自检，不合规直接列出是哪一条并退出）

- 建议每段 **10–40 字**；脚本强制下限 10 字（短于 10 字报错）；
- **不许含省略号**（`……` 或 `...`）：只接受连续原文片段，拼接过的片段直接报错；
- 在原文里 **唯一**（找不到或出现多处都算错）；
- `should` 的片段必须落在 `phase` 所选阶段**之前**（阶段之后的内容他不可能记得）；
- `should` 为空的行没有意义，至少给一条。

`should_not` 不受阶段限制 —— 越界正是要量「阶段之后 / 没参与的事被检索出来」。

## 判定方式

命中按**原文位置区间重叠**：标注片段与返回的前 3 段文本都换算成原文规范化坐标，
区间相交即算命中（命中段被截断到只看得到片段前半也算）。因此不依赖场景怎么切，
以后重切场景或改成按事件入库，标注不用重做。

## 跑法（0b，在服务器上）

标注文件随脚本 `docker cp` 进容器后运行，结果只会写进
`docs/evidence/<evidence-id>.json` 并登记清单（正文引用写 `ev:<id>`）：

```bash
cd /app && PYTHONPATH=/app python /tmp/eval_recall.py \
  --user-id <该用户> --card-id <角色卡> \
  --cases /tmp/recall-<名字>.jsonl --evidence-id <已登记的 id>
```

- 只读：不写库、不建会话、不调大模型；
- 用 `--user-id` 读该用户自己的百炼 key；没配 key 时以
  「请先在设置页配置阿里云百炼 API Key，配置后才能使用向量检索」退出；
- 每条查询只花一次查询嵌入（50 条合计远低于 ¥0.01）。

## 结果格式

```json
{"r_at_3": 0.7, "leak_rate": 0.1, "n": 50,
 "per_query": [{"id": "q01", "hit": true, "leak": false, "top3_chunk_ids": ["scene_3", "..."]}]}
```

`r_at_3`：前 3 段命中了「该找回片段」的查询占比；`leak_rate`：前 3 段出现了
`should_not` 片段的查询占比。
