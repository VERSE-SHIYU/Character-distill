# 设计文档：角色主动疏远（Active Estrangement）

> 队列 8 | 状态：设计冻结归档（v2，调研修订版） | 前置：不动代码，P1 影子模式为解冻条件
> 基准代码：main @ 99667f3 | 作者：Claude（远程分析）/ 评审：Shiyu

## 0. 一句话与定位

角色在被持续冒犯后**主动**进入疏远状态：好感缓降、语气持续变冷、且不因一句道歉立刻回暖——要哄。关系变化的发起权第一次从用户手里部分转移给角色。

**为什么是我们做（差异化论证）**：2025-26 年学界密集批评伴侣类 AI 的系统性谄媚——对 17,000+ 条真实人机对话的分析证实 AI 伴侣动态模仿用户情感并放大正面情绪，即使面对越界内容也照单迎合，并呼吁将此类系统作为高风险对象重新设计（Chu et al. 2025）；Replika 的"无条件支持"目标已被证实会正常化甚至美化自毁行为（Zhang et al. 2025）。而工业界扫描（2026-06）显示 Character.AI / Replika / Talkie / Chai / Janitor **无一实现主动疏远**——参与度导向的商业模式在结构上不允许角色冷落用户。本产品为 BYOK 模式，无续聊率 KPI 绑架，是**结构上唯一能做"有代价的关系"的位置**。主动疏远与既有 anti-sycophancy 系统（assertion_confidence 门控）一脉相承：学界点名的问题，我们在架构层解。

## 1. 为什么现有机制不够

现有全部机制都是**被动逐轮响应**：

| 资产 | 位置 | 局限 |
|---|---|---|
| per-turn clamp（±5/-8） | affinity_service.py L45-52 | 单轮钳位，无跨轮记忆 |
| guard 字段 + 沉默机制 | chat_engine.py L951+ | 单轮态度，冷却后即消失 |
| grudge_inertia（记仇） | schema.py L57，仅 prompt 引导 | LLM 软约束，无代码保证 |
| affinity_baseline set-point | affinity_service.py L131+ | 只约束回归，不产生主动行为 |

缺的是一个**跨轮持续状态**：冒犯累积 → 状态切换 → 持续生效 → 有条件解除。这正是状态机。

## 2. 状态机设计

```
正常 ──[酝酿条件]──> 酝酿 ──[进入条件]──> 疏远中 ──[解除条件]──> 缓和期 ──[巩固]──> 正常
        （自愈可退回）  │                     │                       │
                       └──[窗口滑出]──> 正常  └──[再次冒犯]────────────┘（回疏远中，计数+1）
```

`normal → brewing → active → cooling → normal`

### 2.1 进入条件（量化，代码判定）

滑动窗口 **最近 8 轮** 内满足任一，`brewing → active`：
- **累计条件**：评估管道产出的 affinity delta 为负的轮次 ≥ 4 且累计降幅 ≥ 12
- **雷点条件**：`psyche.triggers` 命中（由评估 LLM 标记，见 §4 接口 B）≥ 2 次
- **急降条件**：单轮触发 clamp 下限（-8 被钳位说明原始判定更狠）且 guard ≥ 75

窗口数据来源：评估管道已逐轮产出 delta（EvalResult），只需环形缓冲记录，**无新 LLM 调用**。

### 2.2 疏远中（状态效果）

代码层（硬约束）：
- affinity 正向 clamp 临时收紧：`AFFINITY_DELTA_UP 5 → 1`（好话没用，杯水车薪）
- 每轮被动缓降：evaluation 后额外 `-1/轮`（衰减到 floor 为止，floor = max(0, baseline - 15)——低于基线一档半，呼应 set-point 理论：疏远是暂时偏离，不是关系毁灭）
- 沉默机制阈值放宽：`SILENCE_GUARD_THRESHOLD 85 → 70`、`SILENCE_MAX_PER_DAY 1 → 2`（状态注入，不改全局常量）

Prompt 层（人格表达，注入 system prompt 疏远段）：
- 「你正在和对方疏远。语气冷淡克制，回复变短，不主动展开话题，不用亲昵称呼。这不是赌气一轮，是你真的在收回信任。你的记仇程度是【{grudge_inertia}】。」

### 2.3 解除条件（要"哄"的机制核心）

**不是道歉触发，是持续行为触发**。滑动窗口 **最近 N 轮** 内：
- 正向轮次 ≥ N-1（几乎不能再犯错）
- 且评估 LLM 标记"真诚修复行为"≥ 2 次
- N 基数由 `grudge_inertia` 决定：大度=4，一般=6，记仇=10
- **stage 修正**：进入疏远时 stage 为"亲近"及以上，N +2（越亲近伤得越深，恢复越慢——错误发生在关系深处时信任恢复轨迹更长，Kahr et al. 2024）

**修复行为按人格分型**（HRI 实证：心智感知调节修复策略有效性——被感知为有情感者道歉更有效，被归因意图者解释更有效，Esterwood & Robert 2023b）：评估 prompt 标记 `repair_signal` 时区分类型（道歉/解释/行动补偿/戳中 soft_spots），角色吃哪种由 `psyche.soft_spots` 与人格门控——感性角色吃真诚道歉，理性角色吃解释与行动。

**关键**：解除进入的是**缓和期**（affinity 正向 clamp 恢复到 3，仍低于常态 5），缓和期再撑 3 轮无负面才回"正常"。一句"对不起"数学上不可能立即复原——这就是"要哄"。

### 2.4 频控、疤痕与逃生舱

- 同会话进入疏远的次数每日 ≤ 1（复用 `_silence_state` 同款字典模式，独立键 `_estrangement_state`）
- **三振疤痕机制**（HRI 实证：三次信任违背后，道歉/否认/解释/承诺无一能完全恢复可信度——"三振"上限，Esterwood & Robert 2023a）：同会话累计进入疏远第 2 次起，缓和期结束后的 baseline 永久 -2/次，第 3 次起 floor 同步下调 —— 关系可以修复，但反复伤害留疤。上限 3 次疤痕后不再加深（防数值死亡螺旋），但也**不做"角色永久离开"**（见 §6）。
- 疏远最长持续 30 轮，超时自动进入缓和期（防用户死锁挫败）
- 用户体验保险丝：疏远期间前端不显示任何"状态提示"——**全部通过语气表达**，暴露机制=拆穿魔术（与离线时刻同一铁律）

### 2.5 三个时刻（转折外显）

状态机有三个转折点，每个转折点必须被感知为**角色的情绪事件**，否则持续的冷只会被用户归因为"产品变笨了"。与巧思4（跨档一次性提示）同规格，一次性 prompt 注入、用后即清：

1. **进入时刻（brewing → active 的第一条回复）**：一句收束——不是爆发，是把此前已漏出的介意收拢成一次明确的收回（"……算了，当我没说过""你就这样吧"）。**幅度吃 grudge_inertia**：大度角色可能只是"……没什么，继续吧"（自己消化了一半），记仇角色才是重话。
2. **释怀时刻（active → cooling 的第一条回复）**：全机制情绪回报率最高的一句（"……行了，别这副样子""上次的事，翻篇了"）。用户小心翼翼撑了 N 轮，这一句是给他的确认——没有它，哄好与没哄好不可区分，挫败感反噬。
3. **自我消化时刻（30 轮超时舱触发）**：角色"自己气消了"也要有台词质地（"算了……跟你计较这个，我也挺没劲的"），无声恢复等于机制露馅。

原则：**过程克制、转折外显**——持续状态只靠语气承载，状态跳变必须是被看见的角色行为。这与苏醒/重逢/跨档一脉：系统事件翻译成角色的在场，疏远的进入与解除同样是事件。

### 2.6 前兆坡道（brewing 态）

**状态机是方波，人是斜坡。**关系研究证实信任侵蚀是冲突时刻的渐进累积而非单一事件；治疗联盟研究（Safran & Muran）将破裂描述为谱系——一端是微妙的情感退缩、投入减少，另一端才是公开冲突。若前 7 轮如常、第 8 轮突然冷脸，用户看不到"怨在积"，只会觉得角色抽风。

- **进入侧**：窗口内负向计数达到进入阈值**一半**（负向 2 次/降幅 6）时进入 brewing——不动 clamp、不动任何数值，仅注入轻 prompt：「你对 TA 最近的言行有些介意，还没到发作的程度——语气里可以漏出一点点（回复稍短、热情稍减），但不点破。」窗口滑出负向记录即自愈退回 normal，零日志零落库。
- **逐次命中当场反应**（Fallout 4 分级 telegraphing 的验证做法：伴侣不满当场责备、累积到位才威胁离开）：`trigger_hit` 标记除进环形缓冲外，**当轮**即给评估/回复 prompt 一个引导「这次戳到你了，可以表现出来（沉一下/语气一变），程度由你性格决定」。疏远进入时的收束句因此是已被看见的信号的收束，不是凭空爆发——用户回看聊天记录会发现预兆早就在，出戏变成后劲。
- **退出侧温度梯度**：缓和期语气同步给梯度 prompt「你在消气的路上，但还没完全过去——不再冷淡，但回不到从前的热络，偶尔想起那件事会沉默一下」。释怀句是事件，释怀之后的回暖是过程，3 轮巩固期即语气从"缓"滑回"常"的坡道。

一句话：**转折外显、坡道渐变、幅度吃人格**——快慢问题的本质是用户必须能看着怨恨长出来，而不是被通知它存在。

## 3. 与"角色是真人"哲学的对齐（含理论锚）

- 疏远由 `triggers`/`grudge_inertia` 门控 → **不同角色疏远得不一样**：记仇角色进得快出得慢，大度角色几乎不进。人格优先，不是普适惩罚系统。学界已将"违抗型（defiant）AI 伴侣"作为正式研究对象（Leo-Liu 2023, CHB）——会说不的伴侣是被研究证明的真实感来源。
- 正向恢复慢于负向跌落 → **信任不对称原理**（Slovic 1993）：负面事件对信任的冲击远大于正面事件，信任缓慢累积但可瞬间摧毁。clamp 收紧至 +1 与 N 轮修复即此原理的数值化。
- floor 锚定 baseline → 疏远是关系的**弹性形变**而非断裂，符合 set-point 动力学。
- 破裂-修复循环深化依恋 → **Still Face 范式**（Tronick）：破裂在亲密关系中不可避免，且是依恋纽带建立和加深的必要部分。修复成功后可小幅超回 baseline（+2，一次性），"哄好之后关系比之前更近"有发展心理学背书。
- 语气冷淡由 prompt 承载、数值由代码承载 → 双层一致，LLM 演不好也有代码兜底。
- 区分健康与不健康关系的不是冲突的有无，而是**修复的质量与频率**（Gottman）——本机制的产品叙事重心在"哄好"而非"惹怒"。

## 5. 风险清单

1. **评估 LLM 标记不可靠**（trigger_hit 误报）→ 缓解：进入条件全部要求 ≥2 次命中，单次误报不触发。
2. **剧情内冲突误判**（本产品用户玩 CP 小说角色，戏里吵架是常态）→ P1 影子模式必须打点"疑似剧情冲突"样本（delta 为负但上下文含角色扮演冲突剧情特征），评估 LLM 分不清"戏内"与"真冒犯"可能是最大误报源——P1 打点设计不含此项则数据白攒。
3. **用户挫败流失**：疏远做得太真，用户直接删会话 → 缓解：30 轮超时舱 + floor 不低于 baseline-15 + 释怀时刻的情绪回报（§2.5）+ 上线先灰度。**对冲论证**：Still Face 研究支持破裂-修复循环深化依恋——做对了不是留存风险，是留存资产。
4. **与离线时刻互搏**：疏远中的角色不该有"想起你"的重逢问候 → 离线时刻门控增加 `estrangement == normal` 条件（一行，立项时带上）。
5. **多机制同轮叠加**（沉默+疏远+撤回同时触发）→ 定优先级：疏远状态效果 > 沉默 > 撤回，同轮最多表达一种"冷"。
6. **落库字段迁移**：C 项迁移必须幂等 + 双端注册（013/080 的教训已写进检查清单）。

## 6. 不做什么（范围栅栏）

- 不做"角色主动拉黑/永久离开"——floor + 疤痕上限保证关系始终可修复
- 不做前端状态可视化——语气即界面
- 不做跨会话疏远传染（A 卡疏远不影响 B 卡）
- 本期不动 group chat（单聊验证后再议）

## 7. 分期建议（立项后）

- **P1**：接口 A+B（评估标记）+ 环形缓冲，只记录不动作，跑一周攒真实触发率数据 + 剧情冲突误报样本（§5.2）
- **P2**：状态机（含 brewing）+ clamp 查表 + prompt 注入（三个时刻 + 坡道）（数据证明阈值合理后）
- **P3**：沉默联动 + 离线时刻门控 + 超时舱 + 疤痕机制

P1 先行的理由：进入条件的三个阈值（8轮/4次/12降幅）目前是拍的，真实数据校准后再让它咬人——和"先日志再定 B 型已读不回"同一方法论。
