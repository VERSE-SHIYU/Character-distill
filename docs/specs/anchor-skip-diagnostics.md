# 整卡跳过位置检查：日志说清楚错在哪

## 1. 起因

祈灼重蒸（2026-10-18，任务 bac8b73b6380，生产镜像 ca071386）整卡跳过了位置检查，日志只有一行原因，还打了两次：

```
04:33:40 WARNING core.phase_anchoring: 整卡跳过位置检查（锚点位置不严格递增：716034 → 224224）：祈灼
04:33:40 WARNING core.phase_anchoring: 整卡跳过位置检查（锚点位置不严格递增：716034 → 224224）：祈灼
```

这一行看不出是哪个阶段的哪句锚点、落在第几章、是不是回忆，只能回原文手工查（查出来阶段 1 的锚点在第 383 章的章内回忆里）。打两次的原因：`verify` 每调一次就可能打一次，做法打一次，关系态度又打一次（`warn_skip` 只关掉了记忆和字段这两处）。

## 2. 目标（写在实现之前，见 `tests/test_anchor_skip_diagnostics_goal.py`）

1. 每张卡只打一次「整卡跳过位置检查」，四类条目都有内容时也只打一次。
2. 跳过时每个阶段打一行明细，内容为：
   - 阶段号和 label；
   - 锚点原句；
   - 查没查到；
   - 第几章；
   - 规范化位置；
   - 在不在回忆区，在的话是哪一段；
   - 前文 60 字。前文是原文，换行记作「⏎」。
3. 监测汇总行 `[phase_anchoring]` 末尾加 `retro=`，值取 `RetroRegions.summary()`。没标回忆区的写「未标（原因）」。
4. 不跳过时不打明细。

## 3. 做法

- `phase_anchoring.log_skip(phases, source_text, anchors, name)`：打一行原因，再逐阶段打明细。
  - 由 `card_from_draft` 在 `build_anchors` 之后调一次。
  - `verify` 不再打这条日志，`warn_skip` 参数删掉。
  - 明细里每个阶段的锚点**各自**定位：`phase_ranges` 遇到第一处不对就停，单靠它看不到其余阶段。
  - 定位复用 `quotes.locate_anchor`，与核对同一条路。
- `quotes.raw_offsets`：规范化坐标换回原文坐标（`normalized_starts` 的反方向）。
  - 段落边界复用 `paragraph_bounds`，段内用二分查找。
  - 边界拼不回整段时返回 None。这时章号记「章号未知」，前文改取规范化文字。
  - 只给日志用，不参与核对。
- 章号：原文位置对 `chapters.chapter_starts` 做二分查找。没有章节标题的书写「无章节标题」。
