## 二、已定的方向

**顺着 Safari，不跟它对着干。** 键盘弹起时 Safari 自己把页面往上推，这是网页上唯一与键盘同步的动作。

| 依据 | 状态 |
|---|---|
| Telegram 网页版 A：容器高度 = 可视高度 + 页面被推上去的距离，不把页面拽回顶部（`src/util/windowSize.ts`，2026-09-29 版本） | ✅ |
| Telegram 网页版 K：早年的 iPhone 键盘补丁已用 `&& false` 整体关掉（`src/helpers/dom/fixSafariStickyInputFocusing.ts`） | ✅ |
| 阿里 ChatUI 3.8.0：Safari 里不干预键盘；聚焦时只在 iPhone 上给消息列表顶部加 75% 屏高留白，把消息压到输入栏旁边（`Composer/riseInput.js`、样式里的 `.S--focusing .MessageList`） | ✅ |
| 仓库现状相反：容器只取可视高度，并用 `window.scrollTo(0,0)` 把页面拽回（`useVisualViewport.js:25`、`:28-30`） | ✅ |
| 这就是「内容被弹上去、下滑才回来」和「不丝滑」的根因 | ❓ 推断，把握较大，真机确认 |

**网页的上限**：键盘弹起时整页一起上移，顶栏也会滑出屏幕上沿；做不到微信那样顶栏不动。

## 四、模块边界

| 模块 | 只管什么 | 对外接口 |
|---|---|---|
| 键盘层 | 输入框聚焦状态、iPhone 留白、内嵌浏览器里的滚入视野。不改容器高度，不拽页面 | 一个聚焦状态类；一个 hook |
| 聊天骨架 | 顶栏、消息列表、输入栏三段的布局 | 三个插槽 |
| 消息列表组件 | 贴底跟随、回到底部按钮、用户上翻、加载更早、跳到某条 | 页面只传消息和回调 |
| 各页面 | 业务内容 | 只依赖上面三个 |

迁移期间旧的 `useVisualViewport` 仍在全站生效，试点页需要让它对本页不动作。这个让位开关是临时的，全部页面迁完后和旧逻辑一起删除。

1. 点输入框：消息和输入栏随键盘一起上移，最后一条消息贴着输入栏，没有空白。
2. 过程顺不顺，你主观判断，对照 `web.telegram.org/a`。
3. 收起键盘：页面回到原位，没有错位或多出来的空白。

5. 发消息、收到回复时列表自动贴底；往上翻着看时不被拽回。

### 3. 两处补做的方案对比（待你拍板）

**键盘层的做法**

| | 留白式（ChatUI） | 高度公式（Telegram 网页版 A） |
|---|---|---|
| 做法 | 不改容器高度、不监听视口；聚焦时给消息列表顶部加留白 | 仍监听视口，容器高度 = 可视高度 + 被推上去的距离 |
| 依赖 | 只依赖输入框的聚焦和失焦 | 依赖可视高度这个值，而它要等键盘动画结束才更新，还可能不发通知 |
| 可借用代码 | 可以（MIT） | 不可以（GPL-3.0），只能照思路写 |
| 推荐 | **是** | 留作留白式不够用时的补充 |

**贴底跟随的库**

| 库 | 版本 / 许可证 / 兼容 | 判断 |
|---|---|---|
| `use-stick-to-bottom` | 1.1.6，MIT，零依赖，React 16.8–19 | **推荐。** 自带是否在底部的状态和滚到底的方法 ✅ |
| `react-virtuoso` | 4.18.16，MIT，React 16–19 | 虚拟列表，三个列表要重写，偏重 ◻ |
| `react-scroll-to-bottom` | 4.2.0，MIT，2024-05 后未更新，带 7 个依赖 | 不推荐 ◻ |

### 4. 交还给 Safari 之后，谁管什么

| 行为 | 谁管 |
|---|---|
| 聚焦时把输入框推到键盘上方，动作与键盘同步 | Safari |
| 键盘已开时换到另一个输入框 | Safari |
| 打字时光标保持可见 | Safari |
| 收起键盘后页面归位 | Safari；内嵌浏览器里可能留空白，由键盘层修正（照 ChatUI） |
| 被推上去之后，消息仍贴着输入栏 | 键盘层的留白 |
| 新消息到来时贴底、回到底部按钮 | 消息列表组件 |

**你真机只看 3 条**（模拟不了的）：
1. 点输入框，消息和输入栏随键盘一起上移，最后一条贴着输入栏，没有空白。
2. 顺不顺，对照 `web.telegram.org/a`。
3. 收起键盘，页面回到原位，没有错位或多余空白。
