## 0. 目的与达成标准

原著里不好相处的角色，聊天时不被模型拉回「好说话」；关系真的变亲近后，在角色自己的范围内变暖。验收原样三条（进 spec 时不改字）：

1. 同等好感下，角色之间的差别还在；
2. 低好感时，多轮对话不变软；
3. 低宜人性角色进入亲近档所需轮数，明显多于高宜人性角色。

范围：③a 新字段与蒸馏；③b-1 人格块（分面、三档语气）与好感机制（方案 B2）、上一轮信号落库、`affinity_service.py:209` 标签错位。③b-2（「## 想要什么」渲染）并入本稿，作为最后一段（Shiyu 10-07 定；②已合并，接入点在 main 上，见 §4a）。

## 4a. ③b-2「## 想要什么」（v5 并入）

- **做法**：在 `_CORE_SECTIONS`（C26）里「遇事的做法」之后加一行「想要什么」，正文取投影卡的动机（§2 的 `motives`），每条一行。只改这一处；没有动机时整块不出现，位置在「## 遇事的做法」之后、「## 语言风格」之前，都由现有的 `_build_core_sections` 处理。
- **按阶段**：动机是 state 类，读的是投影卡，所以只出现阶段 k 和全程成立的动机（C17）。未定位区的动机不进 prompt（B 的规则）。
- **覆盖面**：和②相同。一对一、agent、群聊、主动消息都经卡片核心层；开场白、苏醒台词、市场 @ 回复是独立短 prompt，不覆盖。
- **不做**：②每 4 轮的临时用户消息只重注入做法表，这次不把动机加进去。动机会不会随轮数变淡，演示卡验收时看。
- **依据**：洗白主要发生在动机字段（2601.04716，已被 EMNLP 2026 接收）；接法由②的 spec §3.2 预留。

## 5. ③b-1 好感机制（方案 B2）

**原则**：模型只报「这一轮发生了哪类事」，状态怎么变由代码决定；模型必须先选档，再在该档区间内给一个整数，代码按事件类别和档位区间截断（v6，EIBench 原样）。好感只在发生事件时变，没有事件就不动（v3）。角色之间的差别来自评估时带上这张卡自己的亲近条件、雷点、记仇程度，代码不按性格缩放幅度（v6）。

**依据分级（v3 更新）**
- 「模型检测 + 代码定状态」对「纯 prompt」：**有直接对照**。2606.10051（2026-06 预印本，原文已读）同模型同人设、20 名临床人员 80 场：有状态模块的版本披露随对方表现稳步上升，状态与说出的内容一致率 0.651；纯 prompt 版一开始就高、基本持平，一致率 0.311。同方向的还有 2609.00982 的合成流程（原文已读）、2602.22157 和 Codified FSM（ICLR 2026）（后两篇只读摘要）。
- 「模型报事件类别」对「模型直接给数」：**仍没有对照**，标**自研，有间接依据**。2609.00982 比的是训练过的模拟器和 prompt 驱动的前沿模型；EIBench 的「必须选档」里，选哪档、正还是负仍是模型定的。
- 不依赖模型宽松程度的，是代码里的门槛（基线这条线、正向大档门槛、进亲近档要累计 `met_condition`）。这些门槛反过来依赖模型能否把「客气」和「做到了亲近条件」分开。缓解：`met_condition` 必须同时给出满足的是第几条（`met_condition_index`），代码核对编号，否则降为 `friendly` 并 warning（T15）。逐轮分类本身不稳（2609.00982 κ=0.427；2606.10051 检测器 ICC 0.60–0.78），能否真正减偏只能靠验收第 3 条和上线后监测。
- 成本（v6）：每轮评估仍只有现有的一次调用（`evaluation_pipeline.py:129`），以上都并进这一次，不新增调用。PatientAct 每轮多步调用（反应、行为、抗拒、信任更新各一次）的做法不采用，只采用「结合档案判断、默认不变」这一点。
- 跨角色快慢怎么验（v6）：文献里没有「跨角色轮数比」这种指标。PatientAct 报告模型评委在节奏、抗拒两项上与人的相关只有 0.29、0.22，还把去掉一个组件的版本评得比完整版高。所以验收第 3 条的跨角色部分不设自动门槛，演示卡验收时由人读对话判定。

**评估输出**（`build_evaluation_prompt` 的 JSON 段）：去掉 `affinity` 绝对值，换成：

| 字段 | 取值 |
|---|---|
| `affinity_event` | `met_condition`（做到了亲近条件之一）/ `friendly`（一般友好）/ `neutral`（闲聊；**敷衍和纯应答如「嗯」「哦」也算这一类，不算 `friendly`**）/ `offended`（冒犯）/ `trigger`（触雷）/ `repair`（道歉、解释、补偿） |
| `affinity_tier` | `small` / `medium` / `large` |
| `affinity_delta`（v6） | 该档区间内的整数：small 1–2，medium 3–5，large 6–8。只取大小；正负由事件类别定，代码不采信模型给的符号 |
| `met_condition_index` | 事件为 `met_condition` 时必填：满足的是第几条亲近条件 |

亲近条件、雷点、软肋随卡片投影一起写进评估 prompt。记仇程度、波动幅度也写进评估 prompt 作为判档依据（画像非默认时现有 prompt 已有这两句，C12），代码不读它们（v6）。评估 prompt 的档位定义照 EIBench 写，并写明「不要太快接受道歉，一句好话不该带来大幅回升」（v6）。`trust`、`guard` 本轮不改（Q3）。v2 的 `perfunctory` 类别去掉（Q10）。

**代码规则表**（新模块，纯函数；**所有数值是自研，spec 里逐个标出，上线后靠验收看**）：

| 规则 | 定为 | 依据 |
|---|---|---|
| 每档幅度（v6） | small ±1–2，medium ±3–5，large ±6–8，单轮封顶 ±8。档内取模型给的整数，代码截到该档区间。不随 `volatility` 收放；不采用 EIBench 的「极端」档（±8–10） | 文献：EIBench 附录 G 的评分规则；它的关系刻度同为 0–100，不用换算。不按性格缩放：PatientAct、2609.00982、2606.10051 都没有在代码里按性格缩放幅度 |
| 正向大档门槛 | `large` 正向只在事件为 `met_condition` 且之前连续 ≥2 轮非负时生效，否则降一档 | 文献：EIBench「大幅正向通常要前面几轮一致」；「2 轮」借自 2609.00982 的判据「连续至少 2 轮」（原文是给判断方的判据，这里做成代码规则，属改编） |
| 基线是一条线（v3） | 好感低于 `affinity_baseline`：`friendly` 小档加分，最多加到基线。好感在基线及以上：`friendly` 不加分。`met_condition` 不受这条线限制 | 文献（v6 补）：①每个人对新认识的人默认有多喜欢，是稳定的个体差异，并与宜人性相关（社会关系模型的感知者效应：Back et al. 2011；Rau et al.，两项研究 n=312、837；**只读摘要**）。②普通对话到不了深层：2609.00982 里自然对话只到表层那道门，平淡一轮会把状态压回表层；PatientAct 里常规的共情回应信任不变；只寒暄的关系不变近（Hall 2019）。③刚认识时寒暄也会拉近一点（Kleinert et al. 2026）。仍标**自研**的只有一步：线的位置取蒸馏出的 `affinity_baseline` |
| 无事件不动（v3，Q6） | `neutral`：好感不变。**没有向基线的回落** | 文献：2606.10051 不衰减；EIBench 无回落项；会回到基线的是心情不是关系（Kuppens 2010；Scheling et al. 2025）；唯一带「无事件就掉」的 2609.00982，作者自述无依据并承认有缺陷。现有 prompt 的原意也是单向的（C21） |
| 进亲近档的门槛（v6） | 好感跨过 73 需要这个存档内累计 ≥3 次 `met_condition`。所有卡同一个数，用默认亲近条件的卡也是 3 | 文献：2609.00982 到最深层要按顺序挣 3 次、不能跳；PatientAct 从起点到完全敞开是 3 次明显提升。改编处：原文三步的判据各不相同，这里三次用的都是卡片自己的亲近条件。`N_default > N` 没有文献支持，取消 |
| 受伤后退 | `offended` / `trigger` 负向，档位由评估给 | 2609.00982 |
| 道歉修复（v3） | `repair` 用同一张档位表加分，加到「冒犯前的值」为止，不超过。没有待修复的冒犯时，`repair` 按 `friendly` 处理 | 上限：文献（道歉能回升信任，多数研究里回不到冒犯前）；幅度沿用档位表 |
| 记仇（v6，Q16，取代 v4 的调档表） | 代码不再按 `grudge_inertia` 调档。记仇程度写进评估 prompt，由模型判 `repair` 的档位时一并考虑 | 文献支持的是方向：宜人性、宽恕倾向预测是否原谅（Fehr et al. 2010 元分析 r=.22；Hodge et al. 2020 r=.44）；道歉越完整越容易被原谅，冒犯越重越需要（Kirchhoff et al. 2012）；不要太快接受道歉（EIBench 模拟器 prompt）。以上心理学三条**只读摘要片段**。没有文献给出「降一档」这样的代码规则；性格由模型结合档案判断（PatientAct），代码再调一次是重复计算 |
| 敷衍（v4，Q10） | 不单独设类别，并入 `neutral`，好感不变 | 前提已核：`neutral` 定的是 0（上一行「无事件不动」）。两种扣分依据都弱（Hall 2019 按周计；2609.00982 的敷衍下压作者自述无依据）；短回复常见、分类不稳，单独扣分会误伤 |
| 冲突档触发 | 上一轮事件 ∈ {`offended`, `trigger`} → 冲突档。统计口径：评估方式变了，冲突事件的分布也会变；旧日志算出的负分占比只作参考，上线后按新评估方式重新统计 | 文献（v6 补）：关系破裂后说话方式当即改变，而且必须看得出来（2609.00982 §3.3：破裂后给内容加防备，防备是后退的可见证据）；中间状态下语气跟最近一次变化走，不跟累计状态走（EIBench 模拟器 prompt）；每轮先定反应再定行为（PatientAct）。未采用：2609.00982 的防备挂在具体内容上、重新挣回后仍在，我们没有逐条内容的状态。「滞后一轮」是实现约束（评估在回复之后跑，C9） |
| 起点（v3，Q5） | 不改，继续按关系查表（C11、C22） | 好感量的是关系远近（C18），陌生人和谁都一样远。文献：2609.00982、2606.10051 所有人设同一起点，差别在门槛和每一级的表现 |

「冒犯前的值」：最近一段连续冒犯开始之前的好感值。好感回到这个值，或者被 `met_condition` 带过这个值，就清空。**「有待修复的冒犯」不另设标记，就是「冒犯前的值非空」**，一处来源；它随 `affinity_state` 落库（见下「落库」），会话恢复后不丢。

**记仇（v6）**

v4 的调档表取消（见规则表，Q16 待确认；不同意就恢复 v5 的表）。代码里保留的只有：`repair` 加到「冒犯前的值」为止；没有待修复的冒犯时 `repair` 按 `friendly` 处理；`repair` 的 large 按 medium 算（large 只留给 `met_condition`）。

**敷衍并入闲聊后的口子**：基线以下 `friendly` 是加分的。如果评估把「嗯」「哦」标成 `friendly`，好感会靠敷衍慢慢涨，和目标冲突。两处防：评估 prompt 的类别定义里写明（见上「评估输出」）；验收时抽看这类回复被标成了什么，上线后看 `friendly` 占比。

**没有亲近条件的卡（v3，Q7、Q8；取代 v2 的「旧卡」段）**

- 判据只有一条：投影后 `psyche.warming_conditions` 为空。旧卡、蒸馏没产出、当前阶段没有、全部进了未定位区，都算。
- 这类卡用两条**默认亲近条件**，其余规则和别的卡完全一样，进亲近档的门槛同为 3 次，不设 N_default（v6）：
  1. 对方向你说了自己的心事（感受，不是寒暄）；
  2. 对方认真回应了你说的事（听懂、认可、在乎）。
- 依据：文献。亲密来自一方表露、另一方的回应让他觉得被听懂、被认可、被在乎（Reis & Shaver 1988；Laurenceau et al. 1998）；文字聊天里同样成立（Leckfor et al. 2025）；听到对方表露比自己表露更让人喜欢对方（Sprecher et al. 2013）。
- 默认两条写在规则模块里，只定义一处。评估 prompt 和 `met_condition_index` 的核对都从同一个取用函数拿亲近条件，卡上有就用卡上的，没有才用默认的。
- 用户补写（Q8）：写在卡片顶层的 `psyche.warming_conditions`，即全程成立；用户保存不走核对（C23），直接可用。补写后投影不再为空，默认两条不再使用。补写入口随第四步（文字字段可编辑，C25）一起做，不在本稿范围。
- 能重蒸的卡等②③做完后整卡重蒸，不单独做「只蒸亲近条件」。
- 这类卡单轮变化不超过现有的 +5 / −8（T16）。上线瞬间所有进行中会话的好感曲线都会变，这是**有意改变**（目的就是去掉评估偏差），不还原现有曲线；验收时旧卡抽样 2–3 张一起看。

**落库**：上一轮 `affinity_event`、`affinity_tier`、连续非负轮数、本存档 `met_condition` 计数、冒犯前的值（没有待修复的冒犯时为空）写进 `affinity_state`（C14，加键无迁移）；群聊写进 `update_group_affinity` 的同一份 JSON（spec 阶段复核群聊行的结构）。记仇不需要额外的键（v6：代码不再读 `grudge_inertia`）。环形缓冲（C13）保留给影子判定，不再是档位的数据源。

**上线后监测**：`met_condition` 占比（按卡、按是否默认条件分开）；`friendly` 占比；各卡进亲近档所用轮数；冲突档占比。

**附带修复**：`affinity_service.py:209`「性格特征」改读 `personality_traits`，`values` 另起一行「价值观」。
