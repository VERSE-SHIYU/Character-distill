## 发件箱

事务发件箱（microservices.io Transactional outbox；本仓删除同步先例）：业务写入的同一事务里写待发记录，60 秒补发循环是唯一发送方，按写入顺序发，对端 200 才删；同一个邀请码前一条没送到，后面的不越过它。复用表 `cross_border_delete_outbox`。

- 注册：建用户 + 原子占码（`WHERE used_by IS NULL`，失败抛 `InviteCodeUnavailable` → 400，整笔回滚）+ 入队资料与「已使用」。顺带修了同一台两人同时用一个码都能注册。
- 后台生成 / 删除邀请码、换头像：入队；从对端收到的变更不再回传（`propagate=False`）。
- 隐私：「已使用」只带 `{"code"}`（政策 3.2(4)）；资料只带 id / username / home_region / avatar_data（3.2(1)）。
- 已知限制：两台之间「已使用」最长有一轮补发（≤60s）的窗口，其间同一个码可能在两台各被用一次。彻底杜绝需注册时同步问对端，会让注册依赖对端在线，不建议。
